# Security Policy

## Scope

This policy covers:

- This repository (github.com/akash-yadav-dev/fail-products)
- The deployed FailProducts application and its infrastructure (Cloudflare Workers, Neon)

Out of scope:

- Third-party dependencies, unless FailProducts' own use of them is independently
  exploitable. Reporting an outdated package with no demonstrated impact here is
  not a vulnerability report — Dependabot already tracks that.
- A fork or self-hosted copy you run yourself.
- Social engineering, phishing, or physical access to a machine you already control.
- Denial-of-service or brute-force reports that don't point to a missing common
  defense (rate limiting, for example, already exists — see `src/services/security/`).

## Reporting a Vulnerability

Use [GitHub's private vulnerability reporting](https://github.com/akash-yadav-dev/fail-products/security/advisories/new)
for this repository. It reaches the maintainer directly and keeps the report out of
public issues while it's unresolved.

Please include:

- A clear description of the vulnerability and its impact
- Steps to reproduce, or a proof of concept where possible
- Any relevant code, request, or configuration

Do not include real user data, live credentials, or access tokens in a report —
describe how they'd be exposed instead of pasting the actual values.

### AI-assisted reports

A report generated by an LLM without a working reproduction or a real impact
assessment will be closed without a detailed response. AI-assisted analysis is
welcome if you've validated it yourself and it includes reproduction steps and
an impact assessment.

## Response Process

This project has one maintainer, so treat these as targets, not guarantees:

- **Acknowledgment:** within 5 business days.
- **Triage:** within 7 days of acknowledgment, confirming whether it's in scope
  and its severity.
- **Fix:** as soon as practical, prioritized by severity. No fixed SLA — a
  critical, actively-exploitable issue gets dropped everything; a low-severity
  hardening suggestion may wait for a normal release.

## Disclosure

Please don't share or discuss a report publicly — including on social media, in a
public issue, or in a PR — until a fix has shipped. You'll be credited in the fix's
commit or release notes unless you ask not to be.

There is currently no bug bounty program.

## Supported Versions

FailProducts is a single deployed web application, not a versioned library —
only the current `main` (production) is supported. There is no LTS or backport
policy.
